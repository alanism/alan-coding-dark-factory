# Agent task contract

Council synthesis. Identify the host workflow and active stage; a hero lens is optional and grants no authority.

```text
Task ID:
Host workflow / current stage:
Operational role / hero lens or none:
Actual agent / model / reasoning setting:
Approved plan / version / approval reference:
Reference specification / version:
Required preceding gate evidence:
User outcome and deliverable:
Owned files / forbidden paths / workspace:
Dependencies and receiving integration owner:
Allowed tools, data and side effects:
Loaded context and versions (retain required project instructions):
Acceptance checks / approved thresholds:
Budget / stop conditions / escalation owner:
Review independence (artifact inspected, shared context, limitations):
Output artifact / revision:
Actual commands and evidence paths:
Known gaps / blocked dependencies:
Handoff recipient and integration checks:
```

For upstream planning, identify the approved brief and draft references rather than inventing an already-approved build plan. During execution, missing correctness-critical information is a stop condition. A valid Stage 4 handoff lets the builder verify upstream completion without recreating it.

In ACDF, task and authority scopes, existing budgets, claim rules, approval modes and hard stops remain controlling. Use [coordination](../framework/ACDF_coordination.md) when assigning lanes. Outside ACDF, use the host's task and approval rules.
